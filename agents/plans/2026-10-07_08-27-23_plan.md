# SOP Visibility and Archive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add private-by-default SOP sharing, global archive/restore workflow, and role-correct SOP access for admins, mentors, and students.

**Architecture:** Keep SOP authorization in the existing SvelteKit page server actions and filter records before they reach the client. Add `private` and `archived` boolean columns through a forward-only D1 migration, then extend the existing page with role-aware forms and an admin/mentor archive filter.

**Tech Stack:** SvelteKit 2, Svelte 5, TypeScript, Drizzle ORM, Cloudflare D1/SQLite, Zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-07-sop-visibility-and-archive-design.md`

## Global Constraints

- “New SOPs default to private and active.”
- “Existing SOP rows will be backfilled as shared (`private = false`) and active (`archived = false`).”
- “Archive is a single global state, not a per-student preference.”
- “Permanent delete remains admin-only.”
- “Minimize use of custom styling/CSS. Rely on Bootstrap elements and utility classes wherever possible.”
- Never edit an existing applied migration; add the next sequential migration.

## Review Focus

- Student requests for private or archived SOP ids must not receive those records or mutate them; cover in server load/archive tests (Task 3).
- Mentor create/update/archive/restore permissions must match admin management except permanent delete; cover in action tests (Task 3).
- Missing sharing/archive form fields must apply the documented defaults without accidentally publishing or unarchiving; cover in action tests (Task 2/3).
- Invalid, missing, already archived, or already active SOP ids must return controlled failures and make no unintended update; cover in action tests (Task 3).
- The UI must not expose delete/edit/restore/private records to students and must expose the sharing/archive controls to admins and mentors; cover in page markup tests (Task 4).

### Specification review

- The migration, Drizzle defaults, student shared/active query, manager active/all query, selected-SOP filtering, approved-mentor write guard, student archive predicate, conditional archive/restore updates, admin-only permanent delete, and role-gated UI controls match the approved role/state matrix. Server and page tests cover the principal combinations and concurrency cases. `?archived=1` intentionally includes active and archived SOPs, as specified in Task 2, rather than showing archived rows exclusively.
- Deviation requiring follow-up: `update` and `delete` validate only that the submitted ID is nonempty. If the ID does not identify a row, each action currently returns success, contrary to the approved specification's controlled-failure requirement for invalid targets. Add row-change detection and regression tests in a separate product-code task; Task 5 was limited to verification and documentation.
- Browser coverage is the repository's home-page smoke test. SOP page assertions are static markup tests, so an interactive SOP workflow has not been exercised end to end.
